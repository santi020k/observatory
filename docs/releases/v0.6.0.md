# Observatory 0.6.0 release preparation

This is a local release candidate based on `main` at `b936c94`. Publishing remains a separate
GitHub release workflow operation after review, required checks, merge, and deployment verification.

## Scope

- Retain Observatory's violet palette, private workspace, API boundaries, and provider definitions.
- Adopt Lumen 4 public components and motion contracts throughout the ten rendered route families.
- Consolidate the preserved README edits and chart history fix `07bc24a`.
- Reconcile dependency updates with the latest compatible stable packages. TypeScript 7 is deferred
  because Astro check and the maintained ESLint packages currently require TypeScript 5 or 6.
- Keep authentication storage, recovery behavior, D1 tables, and migrations unchanged.

See the [design guide](../design-system.md) and [visualization guide](../visualization-roadmap.md)
for the supported component and interaction contracts.

## Validation

The local release candidate passed these checks after a clean, frozen, offline installation:

- `pnpm verify`: zero-warning ESLint, Astro check (54 files, no diagnostics), strict TypeScript,
  178 tests, Astro Doctor (100/100), production dependency audit, and API/web production builds.
- `pnpm release:status` and `pnpm release:validate-tag -- v0.6.0`: consumed Changesets and consistent
  0.6.0 versions across the root and five workspaces.
- Forty before and forty after screenshots across ten route families, at 375px and 1440px in both
  light and dark themes. Every route had one main heading, expected HTTP status, no horizontal
  overflow, and no unhandled page errors.
- Ten browser interaction checks covering keyboard navigation, modal focus and background isolation,
  theme persistence, filters and live counts, range navigation, saved and system reduced motion,
  navigation without JavaScript, and additional 320px and 800px responsive checks.

Browser checks used the built Astro/Cloudflare app with synthetic fixtures on a loopback API.
Production metrics, sessions, credentials, and external mutations were excluded. Screenshots remain
temporary verification evidence rather than committed application assets. Independent subagent
review found no remaining actionable findings in the complete release diff.

Run the same repository gates again before the release PR. Local checks do not establish GitHub CI,
production deployment, or post-release health.

### Remaining upstream notices

The production audit is clean. The complete tooling audit still reports one low-severity KaTeX
advisory by package version; the installed package carries the upstream security fix and passes
15 behavioral regression checks. The advisory remains visible. See the
[security maintenance guide](../dependency-security.md) for the patch, provenance, removal criteria,
and the two upstream ESLint peer-metadata constraints.

The web build reports a 518 kB optional Lumen phone-input chunk above Vite's 500 kB notice threshold.
Observatory does not render a phone input; this is an upstream lazy component emitted by the shared
UI runtime. The threshold and Lumen's public integration are unchanged.

## Local integration and branch cleanup

The release contains the recovered chart correction `07bc24a`, shared ESLint upgrade `d45c7e1`,
dependency update branch `a2fe44e`, and shared pnpm action update `0a401e1`. Dependency conflicts were
reconciled against the compatible stable graph rather than reintroducing removed packages or
unsupported TypeScript 7. The original uncommitted README changes are preserved in the refresh.

The missing temporary chart worktree's stale metadata was pruned after recovering its commit.
`chore/update-eslint-configs` remains because another chat owns its clean checkout; it has no unique
commits outside this release. `main` and remote branches remain intact. This preparation creates no
remote branch, pull request, tag, release, or deployment.

## Rollback and deployment

This release introduces no database migration, secret change, or public API change. The existing
protected GitHub deployment workflow remains authoritative. If the deployed UI regresses, use an
authorized rollback to the last verified immutable Worker versions or merge a corrective release
through the same workflow. Preserve D1 data and authentication tables during either recovery path.

Do not create a version tag or GitHub Release locally. After the release PR and production checks
pass, dispatch the documented `Publish release` workflow against the merged `main` commit.
